# Kudi Log

A personal daily spending tracker for Nigerians. You type spending the way you'd say it ("suya 2k, transport 1,500, data 1k"), Kudi Log reads it, and at the end of the day you get a clear summary of where your money went. Works as an installable web app (PWA) and as a Telegram bot on the same backend.

Built for fun and as a portfolio piece, so **polish and design quality matter more than feature count**. A handful of real users is success.

## Non-negotiables

1. **Design is the product.** Every screen must feel fast, smooth and beautiful. Follow `docs/design.md` and `design/tokens.css` exactly. Never ship a default-looking screen.
2. **₦0 running cost.** Only free tiers. No WhatsApp Business API (Nigeria charges per message), no paid SMS, no paid AI, no payments in v1. See `docs/costs.md` before adding any service.
3. **AI never does maths.** The AI only turns messy text into `{item, amount, category}`. Totals, averages, comparisons and summaries are computed in code.
4. **Rules first, AI second.** `lib/parser.ts` handles common entries for free. Only the pieces it can't read go to the AI, through the single function in `lib/ai.ts`, so the provider can be swapped (Groq or Gemini).
5. **Lagos time.** A "day" is the Lagos calendar day (UTC+1, no DST). Use `lib/dates.ts`, never `new Date().toISOString().slice(0,10)`.
6. **Money is whole naira integers.** Display as `₦1,500` with `lib/money.ts`. Never show "1.5k" in the UI.

## Stack

| Part | Choice | Why |
|---|---|---|
| App | Next.js 15 (App Router) + TypeScript | One codebase for web, PWA and the bot webhook |
| Styling | Tailwind CSS v4, theme mapped to `design/tokens.css` | Fast to build a custom look |
| Motion | `motion` (Framer Motion) | Count-up totals, list enter/exit, swipe to delete |
| Bottom sheets | `vaul` | Native-feeling sheets on mobile |
| Auth + DB | Supabase (Postgres + Auth, free tier) | Google sign-in and email magic links, row-level security |
| AI fallback | Groq free tier (`llama-3.1-8b-instant`), Gemini free tier as backup | Free |
| Bot | Telegram Bot API (webhook to `/api/telegram`) | Free, no per-message fees |
| Hosting | Vercel Hobby, with a daily cron for the 9 PM summary | Free |
| Tests | Vitest | Parser and summary logic |

## What's already here

- `supabase/migrations/`: tables `profiles` and `entries`, RLS policies, and the signup trigger. New schema changes go in a new migration (`supabase migration new <name>`), never by editing an applied one.
- `supabase/config.toml` + `supabase/templates/`: the local Supabase stack (Docker via OrbStack) and the sign-in email (link + code).
- `lib/parser.ts` + `tests/parser.test.ts`: the rule parser, 20 passing tests. It handles `2k`, `2.5k`, `2k5`, `1.2m`, `₦3,500`, `N1200`, `500 naira`, "2k for suya", and splitting on commas, "and", new lines.
- `lib/categories.ts`: 12 categories with a Nigerian keyword list (suya, danfo, keke, NEPA, DSTV, offering, and so on).
- `lib/dates.ts`, `lib/money.ts`: Lagos day and naira helpers.
- `lib/summary.ts` (`summarizeDay` and friends, pure and tested) + `lib/day-summary.ts` (`loadDay(db, userId, day)`): the one place a day's summary is computed. The summary screen, share card and Today use it; the bot's `/today` and the 9 PM message should too.
- PWA: `app/manifest.ts`, `public/sw.js` (network-first pages with an `/offline` fallback, cache-first `/_next/static`, never `/api` or `/auth`; bump `VERSION` when you change it), `components/Pwa.tsx` (registers the SW in production only; the install card after the 3rd log). Icons are generated by `node scripts/make-icons.mjs`. `htmlLimitedBots: /.*/` in `next.config.ts` keeps metadata (manifest link, apple tags) in `<head>`; don't remove it or the app stops being installable.
- `assets/fonts/`: static TTFs for the share card (`next/og` can't use variable fonts or CSS variables).
- `design/tokens.css`: every colour, type size, radius and motion value.
- `docs/design.md`: the design direction, every screen and every interaction.
- `docs/costs.md`: the free-tier plan and when each limit would bite.
- `.env.example`, `vercel.json` (cron), `package.json` (Next, Supabase, Vitest).

## Build order

Do these in order. Each step ends with something you can open on a phone.

1. **Shell + design system.** Add Tailwind v4, map `design/tokens.css` into the Tailwind theme, load Bricolage Grotesque + Inter with `next/font/google`. Build the shared components first: `PillButton`, `LogBar` (the black "What did you spend on?" bar), `EntryRow`, `CategoryChip`, `HeroTotal` (with count-up), `Sheet`. Make a `/dev/components` page that shows them all.
2. **Auth.** Supabase Google sign-in plus email magic link. Welcome screen as in the mockups. Middleware refreshes the session.
3. **Logging.** `lib/ai.ts` (`parseWithAI(pieces: string[]): Promise<Array<ParsedItem | null>>`, one result per piece in order so the UI can ask "How much was it?" about the nulls; Groq via its OpenAI-compatible endpoint, strict JSON, validate every field, all nulls on any failure; pieces with no number are never sent). `lib/entries.ts` with `logText(db, userId, text, source)` that runs `ruleParse`, sends `unparsed` to the AI, inserts rows, and returns them. `POST /api/entries`. Quick log sheet with live parsing preview on the client (import `ruleParse` in the browser too, it has no dependencies).
4. **Today screen.** Hero total, category bar, entry list, swipe to delete with Undo toast, tap to edit (sheet). Optimistic updates.
5. **Summary.** `lib/summary.ts` pure functions: `summarizeDay(entries, history)` returns total, count, by-category sorted, biggest item, comparison with the same weekday average over the last 4 weeks, streak. Unit-test it. Summary screen and the shareable card (render with `next/og` `ImageResponse` so it can be shared as a picture).
6. **Week insights.** 7-day bar chart (plain divs or SVG, no chart library needed), categories with change vs last week, one plain-English insight computed in code.
7. **Telegram bot.** `/api/telegram` webhook checks `X-Telegram-Bot-Api-Secret-Token`. Linking: Settings creates a one-time code and shows a `t.me/<bot>?start=<code>` button; `/start <code>` saves `telegram_chat_id`. Commands: plain text logs spending, `/today`, `/week`, `/undo`, `/summary on|off`, `/help`. Inline buttons for Undo and "Fix a category". Uses the service role key, and always filters by `user_id`.
8. **Nightly summary.** `GET /api/cron/daily-summary` (checks `Authorization: Bearer $CRON_SECRET`), runs at 20:00 UTC = 9 PM Lagos, sends the summary to everyone with `nightly_summary = true` and a linked chat.
9. **PWA.** `app/manifest.ts`, icons (192, 512, maskable), a small service worker for offline shell, "Add to home screen" prompt after the third log.
10. **Polish pass.** Empty states, loading skeletons, error toasts in plain language, dark mode, haptics, Lighthouse 95+ on mobile.

Later (not v1): Who owes me, Rent Ready savings goals, shop mode.

Months, history and money (added after v1):
- `lib/months.ts` (calendar months, fair month-to-date comparisons, the 12-month view), `lib/money-left.ts` (money left, daily pace, runway, budget status), `lib/periods.ts` (history filters). All pure and tested.
- Insights is `/insights` (week), `?view=month&m=YYYY-MM`, `?view=year`. History is `/history?q=&period=&day=` (keyset paging in `lib/history.ts`). Money is `/money` (`lib/money-data.ts`, `/api/money`, budget via `PATCH /api/profile`). Bot: `/money`.
- Totals over many rows are summed in Postgres (`monthly_totals`, `spend_total`, `spent_since` in the migrations), never by fetching rows: Supabase caps a query at 1,000 rows.
- Money left = latest "set" + money added after it - spending logged after it (by created_at). We never connect to banks.

Voice (added after v1): `components/useVoice.ts` (browser speech recognition, else record and `POST /api/transcribe`), `lib/transcribe.ts` (Groq Whisper, never stores audio), `lib/voice-text.ts` (`cleanTranscript`: pure, tested, turns what speech engines write into parser-friendly text). Telegram voice notes go through the same `transcribe()` and reply with "I heard: …".

## Commands

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # vitest
npm run typecheck

# Local Supabase (needs OrbStack running)
npm run db:start   # API :54321, Studio :54323, Mailpit (emails) :54324
npm run db:reset   # rebuild the local DB from supabase/migrations
npm run db:stop
```

For the Telegram bot locally, expose the dev server (for example `npx cloudflared tunnel --url http://localhost:3000`) and run `npm run bot:setup -- <public-https-url>` (sets the webhook with the secret, and the command menu). Full steps in `docs/setup.md`.

Bot code: `lib/telegram/format.ts` (pure, tested message text and buttons), `lib/telegram/bot.ts` (handlers, admin client), `app/api/telegram/route.ts` (webhook). Users can't write `profiles.telegram_*` themselves (column grants in the telegram migration); linking goes through `/api/telegram/link`. Apply new migrations locally with `npx supabase migration up` (keeps data); `db:reset` wipes it.

## Conventions

- Server-only secrets (`SUPABASE_SERVICE_ROLE_KEY`, `GROQ_API_KEY`, `TELEGRAM_BOT_TOKEN`) are never imported into client components. Put `import "server-only"` at the top of files that use them.
- Web routes use the user's Supabase session (RLS does the scoping). The bot and cron use the admin client and must filter by `user_id` on every query.
- Keep copy short, friendly and Nigerian-English natural ("Your day in kudi", "Biggest bite"). Never shame the user about spending.
- Every new parser case gets a test in `tests/parser.test.ts`.
- Performance (Lighthouse mobile 95+ on every page): use `m.*` from `motion/react` inside `<MotionProvider>` (LazyMotion, strict), never `motion.*`. Entrance animations that should show before hydration use the CSS utilities `animate-rise` / `animate-grow-x` / `animate-grow-y` (set `--delay`). Load sheets and other tap-only UI with `next/dynamic`. Fonts are trimmed local files: Bricolage has only 700/800, Inter 400 to 700 (docs/setup.md, "Fonts").
